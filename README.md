# Tridock（到货三联台）

骨架：到货预报装载 → 实收入账 → 供应商回执装载 → 三方键对齐与差额处置 → 到货日结案封印。

- 前端 http://127.0.0.1:5900
- API http://127.0.0.1:10900

## 差额处置架构（全局唯一：终态标记 + 审计台账为准）

认短/认溢不是只标命运，而是**回写三腿正式表使三腿一致**，全系统只贯彻这一套口径。
六条链（处置口、标记表、正式三行、痕迹、再次扫描、结案证据、看板、列表）由
`reconcile_service` 一处收口，禁止任何一条链自带口径。

**冲突裁决（唯一口径）**：终态标记与审计台账为准。

- **回写规则**：以实收腿为准。凡与实收不一致的预报/回执腿，插入调整单
  （`ADJ-<差额id>-E/C`，数量为差额量）把该腿合计回写至实收数；原始单据不改动。
  同一键因差额行 id 复用撞上本系统旧调整单时按 `-2/-3` 顺延；被外部单号占用则
  照旧撞 UNIQUE 整笔回滚，不掩盖真实冲突。
- **终态依据**：回写后三腿必须能解释终态（认短/认溢 ⇒ 三腿一致），解释不了整笔回滚，
  绝不落「标记已终态、三行仍拧、痕迹为空」的半截。
- **审计**：每条回写腿在 `disposition_audit` 落一行（旧合计→新合计+调整单行号），
  命运行带处置后三数量快照；回写成功必有旧值审计。
- **事务**：命运翻转、调整单、依据校验、审计、open 对齐物化刷新在同一事务内，
  任一步失败整笔回滚，不留半截命运；并发处置同一差额只有一笔成功。
- **隔离**：终态挂起，只标命运+审计，不回写腿。终态（含隔离）不可再改。
- **结案闸**：未决差额清零 **且 `chain_problems` 为空** 才可结案；结案时把
  认短/认溢/隔离计数快照进批次行；结案后禁止处置回写、禁止重跑、禁止改三腿（写闸）。
- **重跑对账**：该键三数量与上次处置快照一致 → 保留终态命运，且不再产出该键差额行；
  数量变了视为新差额，重新 pending。再次扫描只改差额行，**不得抹台账**。
- **总览/看板**：未决取差额行；终态取审计台账**每键最新一次**，当前已重开为未决的键
  不计终态。看板不再有任何独立加项；`/api/dashboard` 与 `/api/reconcile/chain-check`
  均返回六链自检结果。
- **列表**：差额列表返回处置时三数量 + **当前正式三腿** + 终态能否解释当前数量，
  不与三腿各说各话。

核对脚本：`cd backend && python3 -I tests/verify_disposition.py`
（S1–S7 既有口径；S8 为六链夹具：终态行拧、行齐未决、扫描吞终态、交错半截）

## 启动

```powershell
cd backend
py -3.11 -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
.\.venv\Scripts\uvicorn app.main:app --host 127.0.0.1 --port 10900 --app-dir .
```

```powershell
cd frontend
npm install
npm run dev -- --host 127.0.0.1 --port 5900
```
